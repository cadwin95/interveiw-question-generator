# AI_에이전트_성능_개선 - 면접관 가이드

## AI 에이전트 성능 개선 면접 문제: 면접관 가이드

이 가이드는 "AI 에이전트 성능 개선" 면접 문제에서 후보자의 역량을 효과적으로 평가하기 위해 면접관이 숙지해야 할 핵심 사항들을 정리한 것입니다.

### 핵심 기술 및 개념

면접관은 후보자가 다음 기술 및 개념에 대한 이해도를 가지고 있는지 파악해야 합니다. 후보자가 선택한 개선 방안에 따라 깊이가 달라질 수 있습니다.

1.  **RAG (Retrieval-Augmented Generation)**:
    *   **구성 요소**: 벡터 DB (Vector Database), 임베딩 모델 (Embedding Model), 검색 알고리즘 (Retrieval Algorithm - Similarity Search 등), 청킹 (Chunking) 전략.
    *   **작동 원리**: 사용자 질문을 임베딩하여 벡터 DB에서 관련 문서를 검색하고, 검색된 내용을 LLM 프롬프트에 포함시켜 답변을 생성하는 과정 이해.
    *   **개선 방향**: 임베딩 모델 교체/파인튜닝, 청킹 전략 최적화, 검색 알고리즘 개선 (Hybrid Search 등), 리랭킹 (Re-ranking) 모델 도입 등.

2.  **LLM (Large Language Model)**:
    *   **특성**: 특정 모델(GPT-3.5 등)의 강점과 약점 (환각 현상, 속도, 컨텍스트 길이 제한 등).
    *   **활용**: 프롬프트 엔지니어링 (Prompt Engineering)을 통한 답변 품질 제어, Instruction Following 능력 활용.
    *   **개선 방향**: 더 빠르거나 정확한 모델로 교체 (비용/성능 트레이드오프 고려), 프롬프트 최적화.

3.  **대화 관리 (Conversation Management / Memory)**:
    *   **개념**: 대화의 이전 맥락을 유지하여 일관성 있는 응답을 제공하는 기술.
    *   **구현 방식**: 간단한 이전 대화 요약 (Summarization), 대화 기록을 벡터화하여 검색에 활용, 별도 메모리 모듈 구현 등.

4.  **성능 평가 지표 (Evaluation Metrics)**:
    *   **RAG 관련**: 검색 정확도 (Retrieval Precision/Recall/Accuracy), 답변 관련성 (Answer Relevance), 환각 비율 (Hallucination Rate).
    *   **속도 관련**: 응답 지연 시간 (Latency - TTFT: Time To First Token, Total Latency).
    *   **사용자 만족도**: CSAT (Customer Satisfaction Score), NPS (Net Promoter Score) 등 (측정 방식 이해).

5.  **시스템 아키텍처**:
    *   현재 시스템(LLM + Keyword Search + Basic RAG)의 구성 요소와 데이터 흐름에 대한 기본적인 이해.
    *   개선 방안이 기존 아키텍처의 어느 부분에 영향을 미치는지 파악하는 능력.

### 주의사항 (후보자 평가 시)

1.  **우선순위 선정의 논리성**:
    *   **데이터 기반 판단**: 왜 특정 문제(예: 정확도 40%)가 다른 문제(속도 30%, 맥락 20%)보다 *지금 당장 (1-2주 스프린트 내)* 해결해야 할 가장 시급하고 중요한 문제인지 명확한 근거(사용자 불만 비중, 기술적 파급 효과, 실현 가능성)를 제시하는가?
    *   **현실적 제약 고려**: 1-2주라는 시간 제약과 제한된 자원 내에서 실현 가능한 방안을 선택했는가? (예: LLM 파인튜닝은 보통 1-2주 내에 어려움)

2.  **기술적 깊이와 구체성**:
    *   **뜬구름 잡는 이야기는 아닌가**: "RAG를 개선하겠다"는 추상적인 답변 대신, *어떤* RAG 컴포넌트를 *어떻게* 개선할 것인지 (예: "청킹 단위를 문장 단위에서 의미 단위로 변경하고, BM25와 벡터 검색을 결합한 하이브리드 검색을 도입하겠습니다.") 구체적인 아이디어를 제시하는가?
    *   **핵심 아이디어의 타당성**: 제안하는 기술적 접근 방식이 문제 해결에 실제로 기여할 수 있는 합리적인 방법인가? (예: 단순히 벡터 DB를 바꾼다고 정확도가 무조건 올라가는 것은 아님)

3.  **측정 가능성과 실현 가능성**:
    *   **명확한 KPI 제시**: 제안한 개선 효과를 측정할 수 있는 *단일 핵심 지표(KPI)*를 명확히 정의하고, 왜 그 지표가 중요한지 설명하는가? (예: RAG 정확도 개선 -> 'Retrieval Precision@K' 또는 'Answer Relevance Score')
    *   **실행 계획의 현실성**: 제시된 기술적 단계들이 논리적으로 연결되고, 1-2주 내에 프로토타입 수준이라도 구현 또는 실험이 가능해 보이는가? 필요한 데이터나 사전 작업에 대한 인식이 있는가?

4.  **균형 잡힌 시각 (장단점 및 리스크 인지)**:
    *   개선 방안의 **기대 효과** 외에도 발생 가능한 **문제점이나 우려 사항(리스크)**을 인지하고 언급하는가? (예: "하이브리드 검색 도입 시, 검색 속도가 약간 느려질 수 있는 점이 우려됩니다.")
    *   하나의 개선이 다른 영역에 미칠 수 있는 영향(Trade-off)을 고려하는가? (예: 정확도 개선을 위해 복잡한 로직 추가 시 속도 저하 가능성)

### 질문 가이드 (면접관용)

*   **우선순위 관련**:
    *   "여러 문제점 중 [선택한 개선 영역]을 다음 스프린트의 최우선 과제로 선정한 가장 결정적인 이유는 무엇인가요? 다른 문제(예: [언급되지 않은 주요 문제])는 왜 후순위로 두셨나요?"
    *   "1-2주라는 짧은 시간 제약을 고려했을 때, 이 개선 방안이 가장 현실적이면서도 임팩트가 크다고 판단한 근거는 무엇인가요?"

*   **기술적 실행 계획 관련**:
    *   "[선택한 개선 방안]을 구현하기 위한 핵심 기술 2-3가지를 더 구체적으로 설명해주시겠어요? (예: RAG 개선 시, 어떤 임베딩 모델이나 검색 방식을 고려하시나요?)"
    *   "이 개선 작업을 시작하기 위해 가장 먼저 해야 할 일은 무엇이라고 생각하시나요? 필요한 데이터나 리소스는 무엇일까요?"
    *   "제안하신 방법 외에 다른 기술적 대안은 고려해보셨나요? 있다면 왜 현재 방안을 선택하셨나요?"

*   **측정 및 평가 관련**:
    *   "제시하신 KPI ([후보자가 제시한 KPI]) 외에, 이 개선의 성공 여부를 판단할 수 있는 다른 중요한 지표는 없을까요?"
    *   "이 KPI를 실제로 어떻게 측정하실 계획인가요? (예: 평가 데이터셋 구축, A/B 테스트 등)"

*   **기대 효과 및 우려점 관련**:
    *   "가장 우려되는 점으로 [후보자가 언급한 우려점]을 말씀하셨는데, 이를 완화하거나 해결하기 위한 아이디어가 있나요?"
    *   "이 개선이 성공적으로 이루어졌을 때, 장기적으로 AI 에이전트 시스템 전체에 어떤 긍정적인 영향을 미칠 것으로 기대하시나요?"
    *   "혹시 이 개선 작업이 현재 시스템의 다른 부분(예: 응답 속도, 운영 비용 등)에 부정적인 영향을 줄 가능성은 없을까요?"

*   **종합적 이해도**:
    *   "현재 시스템(LLM + Keyword + Basic RAG)의 가장 큰 한계점이 무엇이라고 생각하시나요?"
    *   "만약 시간이 1-2주가 아니라 한 분기(3개월)가 주어진다면, 어떤 순서로 문제들을 해결해나가시겠습니까?"
