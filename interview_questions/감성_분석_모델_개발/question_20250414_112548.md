## 문제 생성 과정

### 1. 초기 문제
## AI 엔지니어 창의 면접 문제

### 문제 제목
**"감정의 팔레트": 텍스트 기반 감정 분석 및 시각화 엔진 프로토타입 개발**

### 문제 설명
사용자가 입력한 텍스트(예: 일기, 리뷰, 소셜 미디어 포스팅)에 담긴 복합적인 감정을 분석하고, 이를 직관적인 시각적 형태로 표현하는 시스템의 핵심 엔진 프로토타입을 개발해 주세요.

기존의 단순 긍정/부정 분류를 넘어, 인간의 감정은 여러 가지가 혼재되어 나타나는 경우가 많습니다 (예: "시험은 망쳤지만, 친구들과 만나서 기분은 좀 나아졌어" - 실망감과 약간의 즐거움 공존).

**요구사항:**

1.  **다차원 감정 분석:** 주어진 텍스트에서 주요 감정(예: 기쁨, 슬픔, 분노, 놀람, 공포, 혐오 등 Plutchik의 감정 바퀴 또는 Ekman의 기본 감정 모델 기반)을 여러 개 식별하고, 각 감정의 강도(intensity)를 추정하는 로직을 설계하고 구현합니다. (반드시 특정 모델을 따를 필요는 없으며, 합리적인 감정 분류 체계를 직접 정의하거나 선택해도 좋습니다.)
2.  **감정 시각화 매핑:** 분석된 다차원 감정 데이터(감정 종류 및 강도)를 특정 시각적 요소(예: 색상, 도형의 크기/개수, 위치 등)로 매핑하는 규칙을 창의적으로 정의합니다. 예를 들어, '기쁨'이 강하면 노란색 원의 크기를 키우고, '슬픔'이 감지되면 파란색 빗방울 아이콘을 추가하는 식입니다.
3.  **프로토타입 구현:** Python 등 익숙한 언어와 라이브러리를 사용하여 위 1, 2번 로직을 구현합니다. 입력 텍스트를 받아, 분석된 감정 정보(예: `{'기쁨': 0.7, '슬픔': 0.3, '분노': 0.1}`)와 이를 시각화 규칙에 따라 변환한 데이터(예: `{'color': 'mix(yellow, blue, weight=0.7)', 'shape': 'circle', 'size': 8, 'effect': 'subtle_anger_spark'}`)를 출력하는 함수 또는 클래스를 작성합니다. (실제 그래픽 렌더링은 필요 없으며, 시각화 요소를 나타내는 데이터 구조 출력으로 충분합니다.)
4.  **결과 설명:** 왜 특정 감정 분석 접근법을 선택했는지, 감정 시각화 매핑 규칙은 어떤 의도로 설계되었는지, 그리고 시스템의 한계점과 개선 방안은 무엇인지 간략히 설명하는 문서를 작성합니다. (코드 내 주석 또는 별도 파일)

### 평가 포인트
- **문제 해결 능력 및 기술 적용:** 복합적인 감정을 분석하기 위해 어떤 자연어 처리 기술(키워드 기반, 감성 사전 활용, 임베딩 기반 유사도, 사전 학습된 모델 활용 등)을 선택하고 적용하는가? 선택의 근거는 합리적인가?
- **창의적 사고 및 설계:** 제한된 감정 분류를 넘어 다차원적 감정을 어떻게 정의하고 접근하는가? 감정 데이터를 시각적 요소로 매핑하는 규칙이 얼마나 독창적이고 설득력 있는가? (단순 1:1 매핑을 넘어선 복합적 표현)
- **사고 과정 및 커뮤니케이션:** 자신의 설계 및 구현 결정 과정을 논리적으로 설명할 수 있는가? 시스템의 한계점을 명확히 인지하고 개선 방향을 제시하는가? (코드 가독성 및 주석 포함)

### 제약 조건
- 개발 시간은 1시간 30분 ~ 2시간 내외로 제한합니다.
- 외부 라이브러리 사용은 자유롭게 허용되나 (예: NLTK, spaCy, Scikit-learn, Gensim, Hugging Face Transformers 등), **거대 언어 모델(LLM) API를 직접 호출하여 감정 분석 결과를 그대로 사용하는 방식은 지양**합니다. (단, 임베딩 추출 등 보조적 활용은 가능)
- 완벽한 성능보다는 **합리적인 접근 방식과 창의적인 아이디어 구현**에 초점을 맞춥니다. 복잡한 모델 튜닝이나 대규모 데이터 학습은 요구하지 않습니다.
- 최종 결과물은 실행 가능한 코드와 결과 설명 문서(또는 주석)입니다.

### 2. 검증 및 개선
## 검토 결과

전반적으로 "감정의 팔레트" 문제는 AI 엔지니어의 문제 해결 능력, 자연어 처리 기술 이해도, 창의적 설계 능력, 그리고 기술적 커뮤니케이션 능력을 종합적으로 평가하기에 적합하고 흥미로운 문제입니다. 특히 단순 분류를 넘어 복합적 감정 분석과 창의적 시각화 매핑을 요구하는 점은 긍정적입니다.

하지만 몇 가지 부분에서 모호함이 존재하며, 제한 시간 내 현실적인 구현 범위를 고려할 때 지원자가 혼란을 겪거나 과도한 부담을 느낄 수 있는 지점이 있습니다. 특히 감정 분석의 깊이, 시각화 매핑의 구체성, LLM 활용 범위에 대한 명확한 가이드라인이 부족하여 평가의 일관성이 저해될 수 있습니다.

## 개선 사항

1.  **감정 분석 범위 및 기대 수준 명확화:**
    *   **모호성:** "다차원 감정 분석", "복합적인 감정"이라는 표현이 다소 추상적입니다. 어떤 수준의 복잡성(예: 몇 개의 감정 차원, 강도 표현 방식)을 기대하는지 불분명합니다. Plutchik, Ekman 모델은 예시일 뿐, 지원자가 직접 정의할 경우 그 범위가 매우 다양해질 수 있습니다.
    *   **개선 제안:** 기대하는 감정 차원의 개수 범위를 제시하거나(예: "최소 3개 이상의 주요 감정 식별"), 강도 표현 방식의 예시를 더 구체화합니다(예: "0~1 사이의 실수값"). 또한, 시간 제약을 고려할 때 "정교한 모델 튜닝보다 합리적인 접근 방식(예: 키워드/감성 사전 활용, 임베딩 기반 유사도 측정 후 간단한 로직 적용 등) 구현에 집중"하도록 명시적으로 안내하는 것이 좋습니다.

2.  **시각화 매핑 규칙 및 출력 형식 구체화:**
    *   **모호성:** "창의적으로 정의", "복합적 표현"이라는 요구사항은 좋지만, "시각화 요소를 나타내는 데이터 구조 출력"의 구체적인 형태나 기대 수준이 모호합니다. `effect: 'subtle_anger_spark'`와 같은 추상적인 표현은 데이터 구조로 어떻게 나타낼지 해석의 여지가 많습니다.
    *   **개선 제안:** 시각화 데이터 구조의 예시를 좀 더 구체적이고 현실적으로 제시합니다. (예: `{'elements': [{'type': 'circle', 'color': 'rgba(255, 255, 0, 0.7)', 'size': 10}, {'type': 'raindrop', 'color': 'rgba(0, 0, 255, 0.3)', 'count': 5}], 'background_effect': {'type': 'subtle_gradient', 'start_color': '#FFFFFF', 'end_color': '#E0E0E0'}}`) "실제 렌더링 코드가 아닌, 시각화 시스템이 이해할 수 있는 **구조화된 데이터(JSON, 딕셔너리 등)**를 출력하는 것이 목표"임을 강조합니다.

3.  **LLM 사용 제한 범위 명확화:**
    *   **모호성:** "LLM API 직접 호출 지양", "임베딩 추출 등 보조적 활용 가능"이라는 조건이 해석의 여지가 있습니다. 예를 들어, BERT 같은 Transformer 모델에서 임베딩을 추출한 후 간단한 분류 레이어를 얹는 것은 허용되는지, 아니면 임베딩만 사용하고 유사도 기반 분석 등을 해야 하는지 명확하지 않습니다.
    *   **개선 제안:** 허용되는/지양하는 LLM 활용 방식을 더 명확히 구분합니다. (예: "사전 학습된 Transformer 모델(BERT, RoBERTa 등)을 로드하여 텍스트 임베딩을 추출하는 것은 허용됩니다. 이 임베딩을 활용한 유사도 계산, 클러스터링, 또는 간단한 분류 모델(예: Logistic Regression, SVM) 학습 등은 가능합니다. 하지만, **GPT-3/4, Claude 등 외부 상용 LLM API에 직접 텍스트를 보내 감정 분석 결과를 요청하고 그 결과를 그대로 반환하는 방식은 허용되지 않습니다.** 핵심 분석 로직은 지원자가 직접 구현해야 합니다.")

4.  **(선택 사항) 예시 입력 데이터 제공:**
    *   문제 설명에 있는 예시 외에 1~2개의 짧은 테스트용 입력 텍스트를 제공하면, 지원자들이 동일한 조건에서 자신의 로직을 테스트하고 결과를 비교하기 용이해집니다.

## AI 엔지니어 창의 면접 문제

### 문제 제목
**"감정의 팔레트": 텍스트 기반 감정 분석 및 시각화 엔진 프로토타입 개발**

### 문제 설명
사용자가 입력한 텍스트(예: 일기, 리뷰, 소셜 미디어 포스팅)에 담긴 복합적인 감정을 분석하고, 이를 직관적인 시각적 형태로 표현하기 위한 **데이터 구조를 생성하는** 시스템의 핵심 엔진 프로토타입을 개발해 주세요.

기존의 단순 긍정/부정 분류를 넘어, 인간의 감정은 여러 가지가 혼재되어 나타나는 경우가 많습니다 (예: "시험은 망쳤지만, 친구들과 만나서 기분은 좀 나아졌어" - 실망감과 약간의 즐거움 공존).

**요구사항:**

1.  **다차원 감정 분석:** 주어진 텍스트에서 **최소 3가지 이상의 주요 감정**(예: 기쁨, 슬픔, 분노, 놀람, 공포, 혐오 등 Plutchik 또는 Ekman 모델 기반 또는 **자신이 합리적으로 정의한 분류 체계**)을 식별하고, 각 감정의 **강도(예: 0.0 ~ 1.0 사이의 실수값)**를 추정하는 로직을 설계하고 구현합니다. *시간 제약 하에서 완벽한 정확도보다는 합리적인 접근 방식(예: 키워드/감성 사전 활용, 임베딩 기반 유사도 측정 후 로직 적용 등)의 선택과 구현이 중요합니다.*
2.  **감정 시각화 매핑:** 분석된 다차원 감정 데이터(감정 종류 및 강도)를 특정 시각적 요소를 나타내는 **구조화된 데이터(예: JSON, Python 딕셔너리)**로 매핑하는 규칙을 창의적으로 정의합니다. 이 규칙은 감정의 종류, 강도, 조합 등을 반영해야 합니다.
    *   *예시: '기쁨' 강도에 따라 특정 색상(노란색 계열)의 밝기/채도를 조절하고, '슬픔' 강도에 따라 다른 요소(파란색 점 개수)를 추가하며, 두 감정이 공존할 경우 색상 혼합이나 특정 패턴을 데이터 구조에 표현할 수 있습니다.*
    *   *출력 데이터 예시: `{'base_color': 'rgba(200, 200, 0, 0.7)', 'elements': [{'type': 'sparkle', 'count': 5}, {'type': 'tear', 'color': 'rgba(0, 0, 255, 0.3)', 'size': 3}], 'intensity_visual': {'type': 'radial_gradient', 'center_color': '#FFFFFF', 'outer_color': 'calculated_mix_color', 'radius_ratio': 0.8}}`*
3.  **프로토타입 구현:** Python 등 익숙한 언어와 라이브러리를 사용하여 위 1, 2번 로직을 구현합니다. 입력 텍스트를 받아, 분석된 감정 정보(예: `{'joy': 0.7, 'sadness': 0.3, 'anger': 0.1}`)와 이를 시각화 규칙에 따라 변환한 **구조화된 시각화 데이터**를 출력하는 함수 또는 클래스를 작성합니다. (*실제 그래픽 렌더링 코드는 불필요합니다.*)
4.  **결과 설명:** 왜 특정 감정 분석 접근법을 선택했는지, 감정 시각화 매핑 규칙은 어떤 의도로 설계되었는지(데이터 구조와 시각적 표현 간의 연결성), 그리고 시스템의 한계점과 개선 방안은 무엇인지 간략히 설명하는 문서를 작성합니다. (코드 내 주석 또는 별도 README.md 파일)

### 평가 포인트
- **문제 해결 능력 및 기술 적용:** 복합적인 감정을 분석하기 위해 어떤 자연어 처리 기술(키워드 기반, 감성 사전, 임베딩+간단한 모델 등)을 선택하고 적용하는가? *시간 제약 하에서 선택한 기술의 합리성과 구현 완성도.*
- **창의적 사고 및 설계:** 제한된 감정 분류를 넘어 다차원적 감정을 어떻게 정의하고 접근하는가? 감정 데이터를 **구조화된 시각화 데이터**로 매핑하는 규칙이 얼마나 독창적이고 설득력 있는가? (단순 1:1 매핑을 넘어선 복합적 표현 규칙)
- **사고 과정 및 커뮤니케이션:** 자신의 설계 및 구현 결정 과정을 논리적으로 설명할 수 있는가? 시스템의 한계점을 명확히 인지하고 개선 방향을 제시하는가? (코드 가독성 및 주석/문서화)

### 3. 난이도 조정
### 난이도 평가

현재 제시된 "감정의 팔레트" 문제는 AI 엔지니어에게 요구되는 복합적인 역량을 평가하기에 매우 좋은 주제와 형식을 가지고 있습니다. 특히, 단순 분류 문제를 넘어 다차원적인 감정 분석과 창의적인 시각화 매핑이라는 아이디어는 참신하며, 문제 해결 능력과 설계 능력을 동시에 볼 수 있다는 장점이 있습니다.

하지만, **초기 버전의 문제**는 다음과 같은 이유로 **'높음' 또는 '매우 높음'** 난이도에 해당하며, **1~2시간 내에 만족스러운 결과물을 내기에는 다소 어려울 수 있습니다:**

1.  **요구사항의 모호성:** '다차원 감정 분석', '복합적인 감정', '창의적인 시각화 매핑' 등의 표현이 구체적인 기대 수준을 명확히 제시하지 못해, 지원자마다 해석의 편차가 클 수 있습니다. 이는 평가의 일관성을 해칠 수 있습니다.
2.  **감정 분석의 깊이:** 복합 감정을 제대로 분석하려면 단순 키워드 매칭 이상으로 문맥 파악, 감성 사전 구축/활용, 또는 임베딩 기반의 미묘한 의미 차이 포착 등 상당한 기술적 깊이가 필요할 수 있습니다. 제한 시간 내에 이를 구현하는 것은 부담이 큽니다.
3.  **시각화 매핑의 복잡성:** 감정의 조합과 강도에 따라 시각적 요소를 '창의적으로' 매핑하고 이를 '구조화된 데이터'로 표현하는 과정 역시, 명확한 가이드라인 없이는 어디까지 구현해야 할지 판단하기 어렵습니다.
4.  **LLM 사용 제한의 모호성:** '임베딩 추출 등 보조적 활용 가능'이라는 조건이 정확히 어떤 범위까지 허용되는지 불분명합니다. (예: 임베딩 후 간단한 분류기 학습 허용 여부 등)

따라서 주어진 시간(1~2시간) 내에 지원자가 현실적으로 달성 가능한 목표를 설정하고, 평가 기준을 명확히 하기 위한 조정이 필요합니다.

### 조정 사항

1.  **감정 분석 범위 및 기대 수준 명확화:**
    *   분석해야 할 최소 감정 개수(예: 3개 이상)와 강도 표현 방식(예: 0.0 ~ 1.0 실수)을 명시합니다.

2.  **시각화 매핑 규칙 및 출력 형식 구체화:**
    *   출력해야 하는 데이터 구조의 **구체적인 예시(JSON 또는 Python Dict 형태)**를 제공하여 기대 수준을 명확히 합니다.
    *   실제 렌더링 코드가 아닌, **구조화된 데이터 생성**이 목표임을 재차 강조합니다.
3.  **LLM 사용 제한 범위 명확화:**
    *   **허용되는 범위:** 사전 학습된 트랜스포머 모델(BERT 등)에서 임베딩 추출 후, 이를 활용한 유사도 계산, 클러스터링, 또는 간단한 분류 모델(Logistic Regression 등) 학습까지는 허용함을 명시합니다.

4.  **명시적인 시간 제한 및 테스트 케이스 제공:**

    *   지원자가 동일 조건에서 테스트해볼 수 있도록 **1~2개의 간단한 예시 입력 텍스트**를 제공합니다. (선택 사항이지만 권장)

### 채점 가이드

-   **감정 분석:** 완벽한 정확도보다는, **왜** 해당 방식을 선택했는지(예: "시간 제약상 키워드/감성 사전 기반으로 구현했습니다.", "임베딩 유사도를 계산하여 미리 정의된 감정 벡터와의 거리를 측정했습니다.")와 그 구현 완성도를 중점적으로 평가합니다. 직접 정의한 감정 분류 체계도 합리적이라면 인정합니다. LLM 활용 규정을 준수했는지 확인합니다.
-   **시각화 데이터 매핑:** **핵심은 창의적인 규칙 정의와 이를 구조화된 데이터로 표현하는 능력**입니다. 얼마나 복잡한 시각화를 상상했는지가 아니라, 감정 데이터(입력) -> 시각화 데이터(출력) 변환 로직이 명확하고 독창적인지 평가합니다. 출력 포맷(JSON/Dict)을 준수하고, 데이터 필드가 매핑 규칙과 일관되는지 확인합니다. 실제 렌더링 능력은 평가 대상이 아닙니다.
-   **구현 및 설명:** 요구사항 1, 2를 통합하여 입력 텍스트로부터 최종 데이터 구조를 출력하는 **엔드-투-엔드 프로토타입 코드**가 실행되는지 확인합니다. 코드 자체의 품질과 더불어, 자신의 작업 내용을 얼마나 논리적이고 명확하게 전달하는지가 중요합니다. 한계점을 솔직하게 인정하고 개선 방안을 제시하는 것은 좋은 평가를 받을 수 있습니다.
-   **시간 제약:** 2시간 내에 완성된 결과물을 제출하는 것을 목표로 하되, 시간이 부족했더라도 접근 방식과 중간 결과물의 완성도, 그리고 남은 부분에 대한 명확한 설명이 있다면 긍정적으로 평가될 수 있습니다.

    *   **규칙과 데이터 구조의 일치:** 정의한 매핑 규칙이 최종 출력되는 구조화된 데이터(JSON/Dict)의 필드와 값에 정확하게 반영되었는가? 데이터 구조가 시각화 의도를 효과적으로 전달하는가?
    *   **데이터 구조의 적절성:** 생성된 데이터 구조가 시각화 시스템(가상의)이 해석하고 사용하기에 적합한 형태(필드 명명, 값의 타입, 계층 구조 등)를 갖추었는가?
3.  **구현 완성도 및 코드 품질 (Evaluation Criteria 1, 3 연계):**
    *   **엔드-투-엔드 구현:** 입력 텍스트를 받아 최종 구조화된 데이터까지 출력하는 파이프라인이 (부분적으로라도) 작동하는가?
    *   **코드 가독성 및 구조:** 코드가 읽기 쉽고, 함수/클래스 등으로 적절히 모듈화되어 있는가? 변수/함수 이름은 의미를 잘 전달하는가?
    *   **결과 설명의 명확성:** 주석이나 별도 문서를 통해 자신의 설계 의도(분석 방식, 매핑 규칙), 구현 내용, 한계점, 개선 방안을 논리적이고 명확하게 설명하는가? (커뮤니케이션 능력)
    *   **요구사항 및 제약 조건 준수:** 명시된 요구사항(최소 3개 감정, 강도, 구조화 데이터 출력 등)과 제약 조건(시간, LLM 사용 범위)을 잘 지켰는가?

### **질문 가이드 (면접 진행 시 활용)**

1.  **접근 방식 선택 관련:**
    *   "이번 감정 분석 문제 해결을 위해 [지원자가 선택한 방식]을 선택하신 주된 이유는 무엇인가요? 다른 접근 방식(예: [다른 방식 언급])과 비교했을 때 어떤 장단점이 있다고 생각하셨나요?"
    *   "정의하신 감정 분류 체계([지원자가 정의한 감정 목록])는 어떤 기준(예: Ekman, Plutchik)을 참고하셨나요? 또는 직접 정의하셨다면 그 이유는 무엇인가요?"
    *   "텍스트 내에서 여러 감정이 복합적으로 나타나는 경우(예: 기쁨과 슬픔 공존)를 어떻게 처리하도록 설계하셨나요?"
    *   "감정의 '강도'는 어떤 로직으로 추정하셨나요? 이 방식의 한계는 무엇이라고 생각하시나요?"
2.  **시각화 매핑 관련:**
    *   "설계하신 시각화 매핑 규칙에 대해 자세히 설명해주시겠어요? 특정 감정(예: 분노)의 강도가 높아지면 시각화 데이터의 어떤 부분이 어떻게 변하도록 의도하셨나요?"
    *   "두 가지 이상의 감정이 동시에 높은 강도로 나타날 때, 이를 시각화 데이터 구조에 어떻게 반영하려고 하셨나요? (예: 색상 혼합, 요소 추가 등)"
    *   "현재 정의된 시각화 데이터 구조 외에, 감정을 더 풍부하게 표현하기 위해 추가하거나 변경하고 싶은 부분이 있다면 무엇일까요?"
3.  **구현 및 개선 관련:**
    *   "구현 과정에서 기술적으로 가장 어려웠던 부분은 무엇이었나요? 시간 제약 내에서 어떻게 해결하려 하셨나요?"
    *   (코드 리뷰하며) "이 부분의 로직(특정 함수/클래스)에 대해 좀 더 설명해주실 수 있나요?"
    *   "현재 프로토타입의 가장 큰 한계점은 무엇이라고 생각하시나요?"
    *   "만약 시간이 더 주어진다면, 어떤 부분을 가장 먼저 개선하고 싶으신가요? (예: 감정 분석 정확도 향상, 매핑 규칙 고도화, 코드 리팩토링 등)"
    *   "이 시스템의 감정 분석 성능을 어떻게 평가할 수 있을까요?"
4.  **기본 개념 확인 (필요시):**
    *   "텍스트 임베딩이 무엇이고, 이 문제에서 어떻게 활용될 수 있을지 설명해주시겠어요?"
    *   "사전 기반 감정 분석과 머신러닝 기반 감정 분석의 주요 차이점은 무엇이라고 생각하시나요?"

### **주의사항 (면접관 유의점)**

1.  **완벽함보다 과정 중시:** 2시간 내 완벽한 솔루션은 불가능합니다. 결과물의 완성도보다는 문제 해결을 위한 사고 과정, 합리적인 기술 선택, 창의적인 아이디어 구현 시도, 그리고 자신의 작업에 대한 명확한 설명을 더 중요하게 평가해야 합니다.
2.  **핵심 로직 직접 구현 확인:** 특히 임베딩 활용 시, 단순히 외부 API(금지된 LLM) 호출 결과를 그대로 반환하는 것이 아니라, 임베딩 추출 후 유사도 계산, 클러스터링, 간단한 분류 로직 적용 등 *핵심적인 연결 로직*을 지원자가 직접 구현했는지 확인해야 합니다.
3.  **시각화 '데이터' 평가:** 실제 시각화 결과물이 아닌, 시각화를 위한 '구조화된 데이터'를 생성하는 능력을 평가하는 것임을 명심해야 합니다. 데이터 구조의 논리성, 표현력, 규칙과의 일관성을 중점적으로 봅니다.
4.  **시간 제약 감안:** 시간이 부족하여 일부 기능만 구현했거나 미완성 상태일 수 있습니다. 이 경우, 구현된 부분의 품질과 더불어 미완성 부분에 대한 명확한 계획이나 아이디어를 설명하는지를 통해 잠재력을 평가할 수 있습니다.

### **추가 고려사항**

*   **한국어 처리의 특수성:** 한국어 형태소 분석, 띄어쓰기, 조사/어미 변화 등이 감정 분석에 미치는 영향을 지원자가 인지하고 있는지, (시간 제약상 적용은 못했더라도) 언급하는지 확인하면 좋습니다. (예: KoNLPy 등 라이브러리 언급)
*   **주관성의 영역:** 감정 분류나 시각화 매핑은 다소 주관적일 수 있습니다. 정답을 맞추기보다, 지원자가 자신만의 논리와 기준을 얼마나 설득력 있게 제시하는지가 중요합니다.
*   **커뮤니케이션 능력:** 제한된 시간 내에 복잡한 문제를 해결하고, 그 결과를 명확하고 간결하게 설명하는 능력은 AI 엔지니어에게 중요한 역량입니다. 발표 및 질의응답 과정에서의 커뮤니케이션 능력을 함께 평가합니다.
*   **성장 가능성:** 현재의 완성도뿐만 아니라, 문제의 한계를 인식하고 개선 방안을 제시하는 모습을 통해 지원자의 학습 능력과 성장 가능성을 엿볼 수 있습니다.
