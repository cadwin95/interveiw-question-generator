# 실시간_이상거래_탐지_설계 - 면접관 가이드

## AI 엔지니어 면접 문제 (실시간 이상거래 탐지 설계) 면접관 가이드

이 가이드는 면접관이 후보자의 답변을 효과적으로 평가하고 심층적인 질문을 통해 역량을 검증하는 데 도움을 드립니다.

### 핵심 기술 및 개념

면접관은 다음 기술 및 개념에 대한 후보자의 이해도를 파악해야 합니다.

1.  **실시간 스트림 처리 (Real-time Stream Processing):**
    *   대용량 데이터 스트림(초당 수백 건)을 지연 없이 처리하는 기술 (예: Apache Kafka, Apache Flink, Spark Streaming, Kinesis).
    *   5초 이내 처리 요구사항을 충족하기 위한 저지연성(Low-latency) 아키텍처 및 처리 방식 이해.
    *   Time Window 개념 및 상태 관리(Stateful Processing) 이해 (연속된 거래 패턴 분석에 필수).

2.  **이상 탐지 (Anomaly Detection) 방법론:**
    *   다양한 이상 탐지 유형 이해 (Point vs Contextual/Collective). 문제에서 요구하는 Contextual/Collective Anomaly 탐지에 대한 이해도 중요.
    *   지도/비지도/준지도 학습 기반 이상 탐지 모델 (Rule-based, Statistical methods, Clustering, Autoencoder, Isolation Forest, Sequence Models like LSTM/GRU, GNN 등)에 대한 지식 및 장단점 이해.
    *   실시간 추론(Inference) 속도와 모델 복잡성 간의 트레이드오프 고려 능력.

3.  **데이터 품질 관리 (Data Quality Management):**
    *   스트리밍 데이터에서 발생 가능한 품질 문제 유형 (결측치, 이상치, 데이터 형식 오류, 지연/순서 오류, 데이터 스키마 변경 등) 인지.
    *   실시간 환경에서 적용 가능한 데이터 정제/보정 기법 (간단한 보간법, 기본값 설정, 유효성 검사 규칙, 스키마 레지스트리 등) 및 그 한계 이해.

4.  **MLOps 및 시스템 운영:**
    *   모델 성능 모니터링 (정확도, 재현율, 오탐율 등).
    *   오탐(False Positive) 관리 전략 (임계값 조정, 규칙 기반 필터링, 사용자 피드백 활용, 2차 검증 모델 등).
    *   지속적인 모델/시스템 개선 방안 (온라인 학습, 주기적 재학습, A/B 테스팅, 피드백 루프 구축).

### 주의사항 (후보자 답변 평가 시)

1.  **'핵심 아이디어 1가지' 집중 여부:** 후보자가 각 항목별로 여러 아이디어를 나열하기보다, 가장 중요하다고 생각하는 **하나의 핵심 아이디어**를 명확히 제시하고 그 **근거**를 논리적으로 설명하는지 확인합니다. 깊이 있는 설명이 분산된 설명보다 중요합니다.
2.  **'5초 이내 처리' 현실성 고려:** 제안하는 데이터 처리 전략, 모델링 방식, 오탐 관리 방안이 **5초**라는 엄격한 시간 제약 조건 하에서 **기술적으로 실현 가능한지**를 중점적으로 평가합니다. 지나치게 복잡하거나 계산량이 많은 방식은 현실성이 떨어질 수 있습니다. 후보자가 Latency와 Accuracy 간의 Trade-off를 인지하고 설명하는지 확인합니다.
3.  **'Contextual/Collective Anomaly' 이해 및 반영:** 단순 개별 거래 이상(Point Anomaly) 탐지를 넘어, 문제에서 요구하는 **연속된 거래 흐름 속 패턴(Contextual/Collective Anomaly)**을 탐지하기 위한 모델링 아이디어를 제시하는지 확인합니다. (예: 특정 사용자 ID 기준 단기 시계열 특징 추출, 상태 기반 분석 등) 모델 선택 이유가 데이터 특성(사용자별 행동 패턴, 시간적 순서 중요성) 및 탐지 목표와 잘 연결되는지 평가합니다.
4.  **구체성 및 실현 가능성:** 오탐 감소 방안이나 시스템 개선 아이디어가 추상적인 구호에 그치지 않고, **구체적인 실행 방안** (예: 어떤 데이터를 어떻게 활용하여 피드백 루프를 만들 것인가?)을 포함하며 현실적으로 적용 가능한 수준인지 평가합니다.

### 질문 가이드 (심층 질문 예시)

1.  **데이터 품질 관련:**
    *   "제시하신 [데이터 품질 문제] 외에 실시간 스트림에서 발생 가능하며 탐지 모델에 영향을 줄 수 있는 다른 문제는 무엇이 있을까요?"
    *   "선택하신 [데이터 처리 전략]이 5초 안에 완료될 수 있다고 판단한 구체적인 근거는 무엇인가요? 예상되는 병목 지점은 없나요?"
    *   "만약 특정 필드(예: 가맹점 카테고리)의 값이 실시간으로 계속 누락된다면, 모델 성능 저하를 막기 위해 어떤 추가 조치를 고려할 수 있을까요?"

2.  **이상 탐지 모델링 관련:**
    *   "제안하신 [모델링 방식]이 '카드 도용 의심 패턴'의 어떤 특징(예: 시간적 순서, 거래 간 연관성)을 포착하는 데 효과적인가요?"
    *   "해당 모델의 실시간 추론(inference) 속도는 어느 정도로 예상하며, 5초 제약을 맞추기 위해 어떤 최적화 방안을 고려할 수 있을까요? (예: 모델 경량화, 특징 선택, 하드웨어 가속)"
    *   "다른 이상 탐지 모델(예: Autoencoder, GNN 등 언급되지 않은 모델) 대신 이 방식을 선택한 결정적인 이유는 무엇인가요? 고려했던 다른 모델의 한계는 무엇이었나요?"
    *   "사용자별로 다른 정상 거래 패턴을 어떻게 모델에 반영할 수 있을까요?"

3.  **시스템 운영 및 개선 관련:**
    *   "제시하신 [오탐 감소 방안]을 적용했을 때, 미탐(False Negative)이 증가할 위험은 없을까요? 있다면 어떻게 균형을 맞출 수 있을까요?"
    *   "탐지 결과(True Positive, False Positive)를 시스템 개선에 활용한다고 하셨는데, 구체적으로 **어떤 정보**를 **어떻게** 수집하고 레이블링하여 모델 재학습이나 규칙 개선에 사용할 계획인가요?"
    *   "새로운 유형의 카드 도용 패턴이 등장했을 때, 현재 시스템이 이를 얼마나 빨리 감지하고 적응할 수 있을까요? (Concept Drift 대응 전략)"
    *   "이 시스템을 실제 운영 환경에 배포하고 안정적으로 운영하기 위해 가장 중요하다고 생각하는 기술적/비기술적 요소는 무엇인가요?"
