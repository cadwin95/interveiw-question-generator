# 최종_문제 - 면접관 가이드

## AI 엔지니어 면접 문제 분석: 면접관 가이드

**면접 문제:** 실시간 사용자 감정 반응형 뉴스 추천 시스템 프로토타입 개발

이 가이드는 면접관이 위 면접 문제를 통해 후보자의 역량을 효과적으로 평가하기 위해 숙지해야 할 주요 지식, 개념, 평가 포인트, 질문 가이드 등을 제공합니다.

### 핵심 기술 및 개념

면접관은 후보자가 다음 기술과 개념을 이해하고 활용하는지 평가해야 합니다.

1.  **Python 프로그래밍 기초:**
    *   데이터 구조 활용 (리스트, 딕셔너리): 샘플 데이터 생성 및 조작, 추천 로직 구현에 필수적입니다.
    *   함수 정의 및 활용: `recommend_next_articles` 함수를 명확한 입출력으로 구현하는 능력.
    *   조건문 및 반복문: 감정(긍정/부정/중립)에 따른 분기 처리, 기사 목록 순회 등 로직 구현의 핵심입니다.
    *   기본적인 알고리즘 사고: 점수 기반 정렬 또는 규칙 기반 필터링 로직 설계 및 구현 능력.
2.  **AI 결과 활용 능력:**
    *   AI 모델(감정 분석)의 출력을 시스템 입력으로 이해하고 활용하는 능력. (모델 자체 개발 X)
    *   AI 결과(감정)를 비즈니스 로직(뉴스 추천)에 연결하여 의사결정(추천 목록 생성)을 내리는 로직 설계 능력.
3.  **추천 시스템 기본 개념 (간단한 수준):**
    *   콘텐츠 기반 필터링 (Content-based Filtering)의 단순화된 형태: 사용자의 과거 상호작용(기사 카테고리, 감정)을 기반으로 유사한 또는 관련성 높은 콘텐츠(같은 카테고리) 추천.
    *   규칙 기반 시스템 (Rule-based System): 특정 조건(감정)에 따라 미리 정의된 규칙(우선순위 조정, 필터링)을 적용하는 방식 이해.
4.  **문제 해결 및 로직 설계:**
    *   요구사항 분석: 문제 설명을 정확히 이해하고 핵심 요구사항을 파악하는 능력.
    *   논리적 사고: 주어진 조건(감정)에 따라 합리적인 추천 규칙(가점, 감점, 필터링, 다양성 확보 등)을 스스로 설계하고 그 근거를 설명하는 능력.

### 평가 포인트

후보자를 평가할 때 다음 사항에 중점을 둡니다.

1.  **로직 설계의 합리성 및 창의성 (40%):**
    *   **요구사항 반영:** 긍정/부정/중립 감정에 따른 추천 로직이 문제 요구사항(카테고리 기반 조정, 다양성 등)을 충실히 반영하는가?
    *   **논리적 근거:** 설계한 로직(점수 부여 방식, 필터링 규칙)의 근거가 명확하고 합리적인가? (특히, '왜' 그렇게 설계했는지 설명하는 능력)
    *   **중립 감정 처리:** 중립 감정 처리 방식이 단순히 랜덤을 넘어, 어떤 의도(다양성, 인기 기반 등)를 가지고 설계되었으며, 그 선택 이유가 타당한가?
    *   **정보 활용:** `predefined_sentiment`와 같은 부가 정보를 적절히 활용했거나, 미활용 시 그 이유를 설명하는가?
    *   **창의성:** 틀에 박힌 방식 외에 참신하거나 효율적인 로직 아이디어가 있는가? (가점 요소)
2.  **Python 코드 구현 능력 및 품질 (40%):**
    *   **정확성:** 설계한 로직이 의도대로 Python 코드로 정확하게 구현되었는가? 함수는 정상적으로 동작하는가?
    *   **데이터 구조 활용:** 리스트, 딕셔너리 등 Python 기본 자료구조를 문제 해결에 효과적으로 사용하였는가?
    *   **가독성 및 유지보수성:** 변수명, 함수명, 코드 구조가 명확하고 이해하기 쉬운가? 적절한 주석이 포함되어 있는가?
    *   **효율성 (기본 수준):** 불필하게 비효율적인 로직(예: 과도한 중첩 루프)은 없는가? (단, 시간 제약 내 프로토타입임을 감안)
    *   **Pandas 사용 (선택 사항):** Pandas를 사용했다면, 핵심 로직 구현에 도움이 되는 방식으로 활용했는가? 아니면 단순히 라이브러리 기능에 의존하여 로직 이해가 어려운가?
3.  **문제 해결 접근 방식 및 결과 시연 (20%):**
    *   **데이터 생성 및 활용:** 요구사항에 맞는 샘플 데이터를 적절히 생성하고, 이를 시뮬레이션에 잘 활용하였는가?
    *   **시뮬레이션 명확성:** 작성된 시뮬레이션 코드가 감정 입력에 따라 추천 결과가 어떻게 달라지는지 명확하게 보여주는가? 결과 출력 형식이 이해하기 쉬운가?
    *   **완성도 및 시간 관리:** 제한 시간 내에 핵심 요구사항을 완수하려는 노력과 문제 해결 과정을 보여주는가? (완벽하지 않더라도 핵심 로직 구현이 중요)

### 질문 가이드

면접 중 다음과 같은 질문을 통해 후보자의 이해도와 사고력을 심층적으로 파악할 수 있습니다.

1.  **로직 설계 근거 질문:**
    *   "긍정/부정 감정 시, 해당 카테고리 기사의 우선순위를 조정하는 방식을 [점수 부여/필터링]으로 선택하셨는데, 특별한 이유가 있으신가요? 다른 방식과 비교했을 때 장단점은 무엇이라고 생각하시나요?"
    *   "부정적 감정 시, 다른 카테고리 기사를 추천할 때 `predefined_sentiment`를 [활용/미활용]하셨는데, 그 이유는 무엇인가요?"
    *   "중립적 감정 시, [선택한 방식, 예: 다양한 카테고리 노출]을 선택하신 이유는 무엇이며, 이 방식이 사용자 경험에 어떤 영향을 줄 것이라고 예상하시나요?"
    *   "만약 특정 카테고리에 기사가 매우 적거나, 사용자가 반응한 기사 외에 해당 카테고리 기사가 없다면 현재 로직은 어떻게 동작하며, 개선할 부분이 있을까요?"
2.  **코드 구현 및 대안 질문:**
    *   "이 로직(특정 부분 지칭)을 구현할 때 다른 방법도 고려해보셨나요? 예를 들어, [다른 자료구조나 접근 방식]을 사용했다면 어땠을까요?"
    *   "작성하신 코드에서 성능상 병목이 될 만한 부분이 있다면 어디일까요? 기사 수가 매우 많아진다면 어떻게 개선할 수 있을까요?" (간단한 수준의 답변 기대)
    *   "(Pandas 사용 시) Pandas를 사용하지 않고 Python 기본 기능만으로 이 부분을 구현한다면 어떻게 할 수 있을까요?"
3.  **시스템 확장 및 실제 적용 질문:**
    *   "이 프로토타입을 실제 서비스에 적용한다고 가정했을 때, 추가로 고려해야 할 사항은 무엇이 있을까요? (예: 사용자별 감정 이력 관리, 추천 다양성 확보, 실시간 처리 성능 등)"
    *   "감정 기반 추천 시스템이 가질 수 있는 잠재적인 문제점(예: 필터 버블 심화, 감정 편향 유도)은 무엇이라고 생각하며, 이를 완화하기 위한 아이디어가 있을까요?" (채점 가이드의 '면접 시 논의 가능' 항목)
    *   "새로운 사용자가 처음 시스템을 사용할 때(Cold Start)는 어떻게 뉴스를 추천하는 것이 좋을까요?"

### 주의사항

면접관은 다음 사항에 유의하여 평가를 진행해야 합니다.

1.  **AI 모델 개발 능력 평가가 아님:** 이 문제는 AI 모델의 '결과'를 활용하는 능력 평가에 초점을 맞추므로, 감정 분석 모델 자체에 대한 깊이 있는 지식을 요구하지 않습니다.
2.  **정답은 없음:** 로직 설계에는 정답이 없습니다. 후보자가 제시한 로직의 '합리성'과 '근거 설명 능력'을 중점적으로 평가해야 합니다. 독창적인 아이디어는 긍정적으로 평가합니다.
3.  **코드 품질 vs. 동작:** 단순히 코드가 동작하는 것을 넘어, 가독성, 구조, 주석 등 코드 품질을 함께 평가합니다. Python 기본 기능을 활용한 깔끔한 구현 능력을 확인합니다.
4.  **시간 제약 고려:** 제한된 시간 내에 완벽한 코드를 요구하기보다는, 핵심 로직 설계 및 구현 능력이 잘 드러나는지 확인합니다. 시간 부족으로 일부 미흡하더라도 핵심 아이디어가 좋다면 긍정적으로 평가할 수 있습니다.
5.  **소통 및 설명 능력:** 후보자가 자신의 생각과 코드 설계 의도를 얼마나 명확하게 설명하는지도 중요한 평가 요소입니다.

### 추가 고려사항

*   **다양한 감정 입력 테스트:** 면접관은 준비된 여러 감정 시나리오(긍정, 부정, 중립 반복 등)를 제시하여 후보자 코드의 반응성을 확인할 수 있습니다.
*   **엣지 케이스:** 후보자가 스스로 엣지 케이스(예: 특정 카테고리 기사 부족, 모든 기사가 특정 감정 톤)를 고려하고 코드에 반영했는지, 혹은 질문 시 대처 방안을 논리적으로 설명하는지 확인할 수 있습니다.
*   **향후 발전 방향:** 면접 막바지에 후보자에게 이 프로토타입을 어떻게 더 발전시킬 수 있을지 자유롭게 아이디어를 제시하도록 유도하여 문제 해결 능력과 시스템적 사고를 엿볼 수 있습니다.
