# 스팸_오탐지_분석 - 면접관 가이드

## AI 엔지니어 면접 문제 숙지 가이드

다음은 제시된 두 가지 AI 엔지니어 면접 문제를 기반으로 면접관이 숙지해야 할 핵심 사항입니다.

---

### 문제 1: 스팸 오탐지 분석

#### 핵심 기술 및 개념

*   **텍스트 전처리 (Text Preprocessing):** 불용어(Stop words) 처리의 영향, 어근 추출(Stemming/Lemmatization)의 부재가 미치는 영향 이해.
*   **TF-IDF (Term Frequency-Inverse Document Frequency):** 작동 원리, 단어 빈도 기반 가중치 부여 방식의 특징과 한계점 (특히 특정 도메인/유형의 텍스트에서).
*   **로지스틱 회귀 (Logistic Regression):** 분류 모델로서의 기본 원리, 선형 결정 경계의 특징, TF-IDF 벡터 입력 시 작동 방식 이해.
*   **모델 평가 지표 (Model Evaluation Metrics):** 오탐(False Positive), 정확도(Accuracy)의 개념 및 오탐 증가 시 문제점 인지 (Precision/Recall 트레이드오프 맥락 이해).
*   **오류 분석 (Error Analysis):** 제한된 샘플을 통해 모델의 오분류 경향성을 추론하고 가설을 설정하는 방법론.
*   **가설 검증 (Hypothesis Validation):** 설정된 가설을 검증하기 위한 실험 설계 능력 (데이터 분석, A/B 테스트, 피처 중요도 분석 등).
*   **피처 엔지니어링 (Feature Engineering for Text):** TF-IDF 개선 방안 (n-gram, 가중치 조절, 단어 임베딩 고려 등), 도메인 특화 어휘 처리.
*   **데이터 중심 AI (Data-Centric AI):** 데이터 품질 및 구성이 모델 성능에 미치는 영향 이해 (특정 유형 데이터 부족/편향 문제).

#### 주의사항

*   **논리적 추론 능력 평가:** 샘플 수가 매우 적으므로 통계적 유의성보다, 주어진 정보(모델 특성, 샘플 패턴)를 바탕으로 논리적이고 설득력 있는 가설을 제시하는지 확인해야 합니다. "할인", "이벤트", "무료" 등 뉴스레터와 스팸 메일에 공통적으로 등장할 수 있는 단어가 TF-IDF에서 높은 가중치를 받아 오탐을 유발할 수 있다는 식의 추론이 중요합니다.
*   **가설 검증 방법의 구체성:** 단순히 "데이터를 더 본다"가 아니라, *어떤 데이터*를 *어떻게 분석*할 것인지(예: 오탐/정탐 메일 간 TF-IDF 값 분포 비교, 특정 단어의 로지스틱 회귀 계수 확인, 정상 뉴스레터 샘플 추가 확보 후 패턴 분석 등) 구체적인 계획을 제시하는지 평가해야 합니다.
*   **해결 방안의 다양성 및 현실성:** 데이터 관점(뉴스레터 샘플 추가 학습, 라벨링 재검토), 피처 관점(n-gram 사용, TF-IDF 가중치 조절, 불용어 사전 확장, 어근 추출 도입 고려), 모델 관점(로지스틱 회귀 파라미터 튜닝, 다른 간단한 모델 고려) 등 다각적인 접근을 제시하는지 확인합니다. 단, 문제 제약 조건 내에서 실현 가능한 방안을 제시해야 합니다.

#### 질문 가이드

*   **(가설)** 제시하신 첫 번째/두 번째 가설의 근거는 무엇인가요? TF-IDF와 로지스틱 회귀 모델의 어떤 특성 때문에 그런 문제가 발생한다고 생각하시나요?
*   **(가설)** 뉴스레터와 스팸 메일 사이에 TF-IDF 관점에서 유사성을 유발할 수 있는 구체적인 단어 패턴이나 특징은 무엇일까요?
*   **(검증)** 해당 가설을 검증하기 위해 추가 데이터가 필요하다면, 정확히 어떤 종류의 데이터가 얼마나 필요하며, 그 데이터를 어떻게 분석하실 건가요? (예: 피처 중요도 분석, 특정 단어 분포 비교 등)
*   **(검증)** 코드를 직접 수정하거나 모델 내부를 볼 수 있다면, 어떤 부분을 확인하여 가설을 검증하시겠습니까? (예: 특정 단어의 TF-IDF 값, 로지스틱 회귀 계수)
*   **(해결)** 제시하신 해결 방안(예: 피처 엔지니어링 변경)이 다른 유형의 메일 분류 성능에는 어떤 영향을 미칠 수 있을까요? 부작용은 없을까요?
*   **(해결)** 여러 해결 방안 중 어떤 것을 가장 먼저 시도하고 싶으신가요? 그 이유는 무엇인가요? 우선순위 결정 기준이 궁금합니다.
*   **(심화)** 현재 모델(TF-IDF+LR)의 근본적인 한계는 무엇이며, 이를 극복하기 위해 장기적으로 어떤 접근을 고려해볼 수 있을까요? (단, 문제 해결 요구사항은 아님)

### 문제 2: 캡셔닝 API 개선

#### 핵심 기술 및 개념

*   **이미지 캡셔닝 (Image Captioning):** 기본 원리, 사전 훈련된 모델의 장단점, 일반적인 실패 사례(Generic captions, Hallucination) 이해.
*   **API 활용 및 제약 극복:** 외부 Black-box API의 한계를 인지하고, 이를 직접 수정하지 않으면서 성능을 개선하는 창의적 방법론 모색.
*   **프롬프트 엔지니어링 (Prompt Engineering):** (API가 텍스트 입력도 받는 경우) 입력 이미지와 함께 적절한 컨텍스트나 지시사항을 제공하여 결과물의 품질을 제어하려는 시도. (캡셔닝 API 특성상 제한적일 수 있으나, 아이디어 발상 측면에서 고려 가능)
*   **후처리 (Post-processing):** API 결과물을 가공/개선하는 기법 (규칙 기반 보정, 동의어/상위어 대체, 다른 모델을 이용한 재작성/필터링 등).
*   **메타데이터 활용 (Metadata Utilization):** 이미지 자체 외의 정보(예: 파일명, 태그, 업로드 경로, 주변 텍스트)를 활용하여 캡션 생성/개선에 도움을 주는 방안.
*   **멀티모달 접근 (Multimodal Approach):** 이미지 캡셔닝 외 다른 AI 기술(예: 객체 탐지(Object Detection), 이미지 분류(Image Classification))을 보조적으로 사용하여 캡션 품질을 높이는 방안. (예: 객체 탐지 결과로 주요 객체 파악 후 캡션에 반영/보강)
*   **하이브리드/앙상블 (Hybrid/Ensemble Methods):** 여러 소스(다른 API, 자체 개발 소형 모델 등)의 정보를 결합하거나, 특정 이미지 유형에 따라 다른 처리 방식을 적용하는 전략.
*   **LLM 활용:** 생성된 캡션을 더 자연스럽거나 상세하게 만들기 위해 대규모 언어 모델(LLM)을 후처리 단계에서 활용하는 방안.

#### 주의사항

*   **제약 조건 준수:** "API 수정/재학습 불가", "대규모 재학습 없이 용이한 통합"이라는 핵심 제약을 철저히 지키는 해결책인지 확인해야 합니다. 자체 캡셔닝 모델 구축 등 제약을 벗어나는 답변은 감점 요인이 됩니다.
*   **창의성 및 실현 가능성:** 제시된 방법들이 기술적으로 타당하고, 기존 시스템에 큰 부담 없이 적용 가능한 수준인지 평가합니다. 참신하면서도 현실적인 아이디어를 높이 평가해야 합니다. (예: 단순히 "더 좋은 API를 쓴다"는 해결책이 아님)
*   **장단점 분석의 균형:** 각 방법의 기술적/운영적 장점과 단점을 명확하고 균형 있게 설명하는지 확인합니다. 모든 방법에는 트레이드오프가 있음을 인지하고 있는지 평가합니다.
*   **다양한 기술 스펙트럼:** 후처리, 메타데이터 활용, 다른 AI 모델과의 연계 등 다양한 AI 관련 기술을 이해하고 응용하는 능력을 보여주는지 평가합니다. 단순히 한 가지 방식에만 얽매이지 않는지 확인합니다.

#### 질문 가이드

*   **(방법 구체화)** 제시하신 [방법 X]를 조금 더 구체적으로 설명해주시겠어요? 예를 들어, 후처리 규칙은 어떤 식으로 만들 수 있을까요? / 어떤 종류의 '다른 모델'을 어떻게 연동하실 건가요?
*   **(방법 구체화)** 메타데이터를 활용한다고 하셨는데, 어떤 종류의 메타데이터가 특히 도움이 될 것이며, 이를 어떻게 캡션 개선에 연결할 수 있을까요?
*   **(장단점)** [방법 Y]의 가장 큰 장점은 무엇이라고 생각하시나요? 반대로, 실제 운영 시 발생할 수 있는 가장 큰 단점이나 어려움은 무엇일까요?
*   **(통합 용이성)** 제안하신 방법들이 "비교적 용이하게 통합 가능하다"고 하셨는데, 실제 시스템에 통합하는 과정에서 예상되는 기술적/운영적 허들은 무엇일까요?
*   **(효과 측정)** 이 개선 방법들이 실제로 효과가 있는지 어떻게 측정하고 평가하실 건가요?
*   **(우선순위)** 세 가지 방법 중 어떤 것을 가장 먼저 시도해보고 싶으신가요? 그 이유는 무엇인가요?
*   **(심화)** 만약 API 재학습이나 파인튜닝이 가능하다면, 어떤 방식으로 접근하시겠어요? (단, 문제 해결 요구사항은 아님)
