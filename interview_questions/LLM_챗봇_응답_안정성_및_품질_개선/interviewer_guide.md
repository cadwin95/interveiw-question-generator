## AI 엔지니어 면접 문제: LLM 챗봇 응답 안정성 및 품질 개선 - 면접관 가이드

이 가이드는 제시된 면접 문제를 활용하여 후보자를 효과적으로 평가하기 위해 면접관이 숙지해야 할 핵심 사항을 담고 있습니다.

### 핵심 기술 및 개념

면접관은 후보자가 다음 기술 및 개념에 대한 이해를 보여주는지 확인해야 합니다.

1.  **LLM (Large Language Models) 기초:**
    *   파운데이션 모델 API (GPT-4 등)의 작동 방식 및 특징 (강점, 약점 - 특히 환각 현상, 일관성 부족 등)
    *   API 기반 모델 활용 시 제약 사항 및 튜닝 가능 범위 이해 (모델 자체 변경 불가)
2.  **RAG (Retrieval-Augmented Generation):**
    *   RAG의 기본 원리: Retriever (문서 검색) + Generator (LLM 응답 생성)
    *   RAG 시스템의 일반적인 실패 지점 (부정확한 검색 결과, 부적절한 청크 크기/전략, 검색된 컨텍스트와 프롬프트 간의 비효율적 통합 등)
    *   RAG 튜닝 기법 (임베딩 모델 선택/미세조정, 청킹 전략 수정, 검색 알고리즘/파라미터 조정, 컨텍스트 활용 방식 개선 등)
3.  **프롬프트 엔지니어링:**
    *   System Prompt, User Prompt, Few-shot Prompting 등 다양한 프롬프트 기법
    *   Instruction Following 능력 향상 기법 (명확한 지시, 역할 부여, 출력 형식 지정 등)
    *   일관성 및 특정 스타일 유도를 위한 프롬프트 설계 전략
4.  **Guardrails (안전 장치):**
    *   챗봇 응답 제어를 위한 가드레일의 필요성 및 종류 (입력/출력 필터링, 규칙 기반 제어, 별도 모델을 이용한 검증 등)
    *   환각 현상 및 부정확한 정보 생성을 완화하기 위한 가드레일 적용 방안
5.  **데이터 분석 및 활용:**
    *   대화 로그, 사용자 피드백 (좋음/싫음) 데이터 분석을 통한 문제 패턴 식별 방법
    *   수집된 데이터를 활용한 단기 개선 방안 도출 (예: 문제 쿼리 식별 -> 해당 쿼리에 대한 프롬프트 수정 또는 RAG 개선 단서 확보)
    *   지속적 개선을 위한 데이터 파이프라인 및 피드백 루프 구축 개념
6.  **평가 지표 (Evaluation Metrics):**
    *   챗봇 품질 평가를 위한 정량적/정성적 지표 설정 (단순 정확도 외 사용자 만족도, 응답 일관성, 환각 비율, 정보 정확성 - 문서 기반 검증 등)
    *   측정 가능한 형태로 지표를 정의하고 모니터링하는 방법
7.  **MLOps / LLMOps (개념적 이해):**
    *   지속적인 모델/시스템 성능 모니터링 및 개선 프로세스 구축의 중요성
    *   데이터 기반 의사결정 및 자동화된 평가/배포 파이프라인의 필요성 (장기적 관점)
8.  **Fine-tuning (개념적 이해):**
    *   파인튜닝의 목적, 장단점, 필요한 데이터셋 유형 (언제 고려해야 하는가)
    *   프롬프트/RAG 튜닝과의 비교 및 트레이드오프 이해

### 주의사항 (후보자 평가 시)

1.  **단기 vs. 장기 구분 및 우선순위:** 후보자가 문제에서 요구한 대로 **즉각적인 개선을 위한 단기 해결 방안**에 명확히 초점을 맞추고 있는지 확인합니다. 장기 방안은 개념적 방향성을 제시하는 수준이어야 하며, 단기 방안이 구체적이고 실현 가능해야 합니다. (예: "모델을 파인튜닝한다"는 단기 방안으로 부적절)
2.  **구체성 및 실현 가능성:** 제시하는 해결 방안이 추상적이지 않고 **구체적인 기술/기법**을 언급하는지 확인합니다. (예: "프롬프트를 개선한다" 보다는 "System Prompt에 역할(기술 지원 전문가)과 어조(전문적, 상세함)를 명확히 정의하고, 관련 기술 문서 섹션을 참조하도록 지시하며, 모범 답변 예시(Few-shot)를 1-2개 포함한다" 와 같이 구체적인 방안 제시)
3.  **데이터 기반 접근:** 문제 진단, 해결 방안 도출, 효과 측정 등 전 과정에서 **수집 중인 데이터(로그, 피드백)를 어떻게 활용할 것인지** 명확히 제시하는지 평가합니다. 가설 기반의 접근과 더불어 데이터 분석을 통한 근거 제시가 중요합니다.
4.  **RAG 및 LLM API 제약 이해:** 후보자가 **상용 API 사용 및 기본 RAG 환경**이라는 제약 조건을 잘 이해하고 현실적인 해결책을 제시하는지 확인합니다. (예: LLM 내부 파라미터 수정 제안 등은 불가능) RAG 시스템의 어느 부분을 어떻게 튜닝할 것인지 구체적인 아이디어를 제시해야 합니다.
5.  **체계적 사고 및 문제 해결 능력:** 문제 원인 진단부터 해결 방안 제시, 효과 측정까지 논리적 흐름을 가지고 체계적으로 접근하는지 평가합니다. 특히, 일관성 부족과 품질 저하라는 두 가지 문제를 각각 또는 통합적으로 어떻게 해결할 것인지에 대한 전략이 중요합니다.
6.  **측정 지표의 적절성:** 제시된 측정 지표가 해결하려는 문제(일관성, 품질)와 직접적으로 관련이 있고, **실제로 측정 가능한 형태**인지 확인합니다. (예: '환각 비율 감소'를 측정하기 위해 구체적으로 어떻게 측정할 것인가? - 샘플링 기반 수동 평가, 자동화된 사실 검증 시스템 도입 등)

### 질문 가이드 (후보자 답변에 대한 심층 질문 예시)

*   **원인 진단 관련:**
    *   "일관성 부족의 가장 가능성 높은 원인이 RAG 검색 결과의 변동성 때문이라고 하셨는데, 구체적으로 어떤 상황에서 검색 결과가 달라질 수 있을까요?"
    *   "환각 현상이 발생하는 주된 이유를 LLM 자체의 한계와 RAG 컨텍스트 부족/오류 중 어느 쪽에 더 비중을 두시나요? 그 이유는 무엇인가요?"
*   **단기 해결 방안 관련:**
    *   "제시하신 프롬프트 엔지니어링 기법 중, **가장 먼저 시도해볼 것**은 무엇이며 그 이유는 무엇인가요?"
    *   "RAG 청킹 전략을 수정한다고 하셨는데, **구체적으로 어떤 방식(예: 크기 조절, 중첩 추가 등)을 고려**하고 있으며, 그것이 현재 문제 해결에 어떻게 도움이 될 것으로 예상하시나요?"
    *   "가드레일 구현 방안으로 '별도 모델 검증'을 언급하셨는데, 현재 제약(상용 API 사용) 하에서 현실적으로 어떻게 구현할 수 있을까요? **규칙 기반 접근 방식**은 어떤 것이 있을까요?"
    *   "수집된 '싫음' 피드백 데이터를 **단기적으로 어떻게 활용**하여 즉각적인 개선에 반영할 수 있을까요? 구체적인 분석 프로세스를 설명해주세요."
*   **장기 관리 방안 관련:**
    *   "지속적인 평가 루프를 구축한다고 하셨는데, **자동화된 평가와 수동 평가**는 각각 어떤 지표에 어떻게 적용하는 것이 좋다고 생각하시나요?"
    *   "파인튜닝 데이터셋 구축 방향성을 언급하셨는데, **어떤 종류의 데이터(예: 고품질 질의응답 쌍, 사용자 피드백 기반 교정 데이터 등)를 어떤 기준으로 수집**하는 것이 가장 효과적일까요?"
    *   "장기적으로 RAG 시스템 자체를 개선한다면, **어떤 부분을 우선적으로 고려**하시겠습니까? (예: 임베딩 모델 교체/파인튜닝, 검색 알고리즘 변경, 지식 그래프 도입 등)"
*   **측정 지표 관련:**
    *   "제시하신 '[특정 지표]'를 **실제로 어떻게 측정하고 추적**할 계획인가요? 필요한 도구나 프로세스가 있다면 설명해주세요."
    *   "사용자 만족도 외에 **응답의 '품질' 자체(예: 사실 정확성, 완전성)를 측정**하기 위한 구체적인 방법은 무엇일까요?"
*   **종합 및 우선순위 관련:**
    *   "제시하신 여러 방안 중, **가장 효과가 빠르고 리소스가 적게 드는 것**부터 순서대로 말씀해주시겠어요?"
    *   "만약 **다음 스프린트(2주) 안에 가시적인 개선**을 보여줘야 한다면, 딱 한 가지 액션만 취해야 한다면 무엇을 선택하시겠습니까?"
